# 跨境服务商对标应用

服务贸易联盟成员在不暴露客户与合同明细的前提下判断海外业务表现。应用接收成员的
合成经营申报与修订，按有依据的可比组生成成员分析，并对联盟对外发布做披露审查。

本目录在仓库既有合成资料（`data/`、`docs/资料契约.md`）之上实现，资料本身受
SHA-256 指纹保护，应用不会改写 `data/` 内任何文件；运行期状态只写入 `state/`，
导出结果写入 `outputs/`，两者均已在 `.gitignore` 排除。

## 1. 业务口径如何落地

### 1.1 收入归属，联合项目不重复进分母

契约规定（`docs/资料契约.md`）：

- 主承包方外部收入 = 申报总额 − 联盟内转包额；
- 合作方外部收入 = 其实际转包服务收入；
- 项目级恒等式：主承包外部收入 + 合作方转包收入 = 合同外部总额 `total_minor`。

`benchmark/attribution.py` 逐申报完成归属，并对全部 360 个项目执行恒等式对账。
基础资料下恒等式零偏差（测试 `test_attribution_revisions.py` 复现历史准确数
27,978,600）；运行期若只有一方提交修订，偏差以 `identity_warnings` 随结果输出，
不会让应用停摆，也不会静默吞掉。

### 1.2 口径变更：可换算、不可比分开处理

`benchmark/calibers.py` 按 `definition_changes` 标注每份申报：

- DC1（design，2026-07 生效）：生效月前的 `gross-prime` 申报，项目在
  `exact_projects` 内的标为 `converted`（有项目级精确换算依据），其余标为
  `incomparable`，只能排除并说明；
- DC2（support，2026-08 生效，无精确换算项目）：两期 `gross-prime` 全部
  不可比；转包合作方按实际服务收入记账，不受主承包口径切换影响，始终可比；
- 生效月之后仍用旧口径的申报保守地视为不可比。

不可比申报绝不进入指标计算，逐份排除原因写入成员分析的 `exclusions`。

### 1.3 观察月与未完成项目

`benchmark/metrics.py`：

- 观察月按企业开业日至资料最新申报月（2026-09）的完整自然月计算，达到指标
  `min_months` 才能参与该指标（rev-hour 6 个月、rev-contract 9 个月、
  concentration 6 个月）；
- 未完成项目保留收入与工时，不按零收益处理，仅不进入 `completed-contracts`
  分母；
- 多指标组合执行共同分母原则：`compatibility.compatible=false` 时只分别成立，
  禁止把不同人群拼成综合结论。

### 1.4 修订与撤回

`benchmark/revisions.py` 是只追加台账：

- `replace` 替换当前声明收入，`withdraw_revision` 撤回此前修订、恢复申报原值；
- 修订版本号必须严格递增，非法修订在落盘前拒绝；
- 每次接收改变状态指纹，成员分析与发布审查都绑定 `data_version`
  （资料指纹 + 状态指纹）。

## 2. 成员对标

`BenchmarkService.benchmark`（`benchmark/service.py`）按申请的参考市场、业务集合
与显式成员范围取交集，逐指标构建可比组：

- 指标定义 `exclude_self=true` 时参考分布剔除发起方自身，企业不能用自己的数据
  同时抬高行业阈值又证明自己超过阈值；
- 输出等权与外部收入加权两套统计、逐期权重表、有效覆盖率、样本标准误（不确定性）；
- 单企业收入占比超过 member 政策 `max_share=0.4` 时给出支配性标记与解释，
  极少数大企业不能在没有解释的情况下决定排名；
- 可比组少于 `minimum_group=6` 时返回不足原因与四步放宽方向
  （取消市场限制 → 放宽业务类别 → 延长时期 → 取消规模层），每一步都重新说明
  比较含义，不相容口径不会被自动合并。

## 3. 联盟发布披露审查

`benchmark/disclosure.py` 实现 `public` 政策（最少 5 个贡献者、最大单企业份额
45%、最小区间宽度 200,000 美分）：

1. **本格判定**：贡献者按实际有正贡献的企业计（范围内无该业务申报的企业不凑数），
   贡献数或集中度不达标则禁止准确值；
2. **组合推导**：把同指标、同统计期、服务范围相容的历史发布与同批申请格写成线性
   约束，用 SciPy `linprog`（HiGHS）求目标企业集合的可行区间；无 SciPy 时降级为
   纯标准库区间传播，结果只会偏宽、不会泄露更窄信息；
3. **相减识别防护**：可行区间窄于最小宽度时，只能发布不窄于该宽度且覆盖可行域、
   下界非负的公版区间；连有信息量的区间都无法构造时拒绝（`deny`）或建议合并
   （`merge`）；
4. **多交叉维度**：发布申请可在 `cells` 中给出多组维度，审查分两轮，第二轮把同批
   拟发布格作为追加约束，单格达标但组合可识别单个企业时一律改判；
5. **不可改事实**：已发布准确数/区间只能追加，合并或扩区间不得改动历史事实，
   不相容口径（服务集合不被包含）不参与约束，避免把混合口径包装成精确结果。

### 撤回不消除披露

`benchmark/ledger.py` 的撤回只追加 `withdrawn` 事件，原发布仍作为审查约束
（`known_cells(include_withdrawn=True)`）。相同接收者已经见过的结果不能通过撤回
变成“从未发生”，再发布同口径信息时可行界不会变宽。测试
`test_withdraw_does_not_erase_disclosed_fact` 与
`test_policy_holds_across_three_publication_rounds` 覆盖多轮发布/撤回。

## 4. 三级权限

`benchmark/access.py`：

- `public`：只含通过审查的准确数或达标区间；
- `member`：组级统计、权重、覆盖与匿名计数，不暴露其他成员企业标识或明细
  （`private_detail=false`）；
- `self`：企业只能读取自身申报、修订轨迹与项目明细，跨企业读取直接拒绝。

## 5. 命令行用法

```sh
# 资料指纹与结构校验
python -m benchmark.cli check

# 接收新申报 / 修订（载荷为 JSON 文件，路径作为参数传入）
python -m benchmark.cli receive-filing examples/new_filing.json
python -m benchmark.cli receive-revision examples/new_revision.json

# 成员对标（输出成员视图）
python -m benchmark.cli benchmark --request REQ1

# 发布申请审查（只审查不写台账）
python -m benchmark.cli publish --request REQ2 --today 2026-11-23

# 审查并把通过的格写入只追加发布台账
python -m benchmark.cli approve --request REQ3 --today 2026-11-23

# 撤回已发布格（事实仍保留为约束）
python -m benchmark.cli withdraw --cell <CELL-ID> --today 2026-11-24

# 企业自身明细 / 当前版本指纹
python -m benchmark.cli self-detail --enterprise E00 --requester E00
python -m benchmark.cli state
```

`--root` 与 `--state` 可覆盖默认资料根目录与状态目录，便于在隔离环境复现。

## 6. 测试

```sh
python tools/check_materials.py
python -m unittest discover -s tests -v
```

测试共 43 个用例，分布：

| 文件 | 覆盖内容 |
| --- | --- |
| `tests/test_materials.py` | 仓库既有资料指纹与损坏检测 |
| `tests/test_attribution_revisions.py` | 归属恒等式、转包识别、修订/撤回链、历史准确数复现 |
| `tests/test_calibers_metrics.py` | DC1/DC2 可比/换算/不可比标注、观察月门槛、未完成项目不按零处理 |
| `tests/test_peergroup.py` | 剔除自身、支配性、共同分母不相容、放宽含义、覆盖与市场过滤 |
| `tests/test_disclosure_policy.py` | 最少贡献者、集中度、最小宽度、历史/同批相减识别、撤回不消除、三轮发布政策 |
| `tests/test_access_versions.py` | 三级权限、版本绑定、版本漂移影响、历史发布保留原依据 |

## 7. 模块地图

```
benchmark/
  materials.py    资料加载、指纹与外键校验
  revisions.py    申报接收、修订/撤回只追加台账、状态指纹
  calibers.py     口径变更规则与可比性标注
  attribution.py  收入归属、转包识别、项目恒等式对账
  metrics.py      指标口径、观察月、共同分母相容性
  peergroup.py    可比组、权重、覆盖、不确定性、支配性、放宽
  disclosure.py   披露审查、LP/传播推导、最小公开策略
  ledger.py       发布台账（只追加、撤回留痕、版本漂移）
  access.py       public/member/self 三级权限视图
  service.py      两条业务流程编排与口径/版本绑定
  cli.py          命令行入口
```
